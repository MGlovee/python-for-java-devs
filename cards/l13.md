# L13 闪卡 · 数据库访问（DB-API 2.0）

> 用法：盖住右列，看左列自问自答，答完再对。做错的那行，在"错"列打 ×。
> 复习节奏：完成当天不算，D+1、D+2、D+4、D+7 各过一遍（`py progress.py review` 会告诉你今天该翻哪张）。

| # | 问 | 答 | 错 |
|---|---|---|---|
| 1 | DB-API 2.0 的五步流水线 | `connect()` → `cursor()` → `execute(sql, params)` → `fetch*()` / `commit()` → `close()`。所有主流库同一套动作 | |
| 2 | JDBC 里 `PreparedStatement` 的角色，Python 里是谁 | **Cursor**。Connection 只是"游标工厂"，执行、取数、`rowcount`、`lastrowid` 都在 cursor 上 | |
| 3 | 占位符分别用什么 | `sqlite3` 用 `?`；`pymysql` / `psycopg` 用 `%s`；SQLAlchemy 的 `text()` 用命名参数 `:name` | |
| 4 | 为什么参数化能防注入 | 值永远不进 SQL 语法层，由驱动绑定；拼接（f-string / `%` / `+`）会让 `' OR '1'='1` 变成语法 | |
| 5 | 表名、列名、`ORDER BY` 能参数化吗 | **不能**，占位符只替换值。必须 `isidentifier()` + 白名单校验后再拼 | |
| 6 | `IN (…)` 值个数不定怎么办 | 按个数生成 `"?, ?, ?"`；**空集合**返回 `WHERE 1 = 0`，不能拼出 `IN ()`（语法错误） | |
| 7 | `with conn:` 提交还是关连接 | 只管**事务**：正常结束 `commit()`，抛异常 `rollback()`，**不关闭连接**。关连接用 `contextlib.closing` | |
| 8 | INSERT 后不 `commit()`，数据去哪了 | 还在未提交事务里：同连接能看见，别的连接看不见；连接关掉就全部回滚。JDBC `autocommit=true` 的直觉在这里是反的 | |
| 9 | 三大库的默认提交行为 | `sqlite3` 否（隐式事务）、`pymysql` 否、**psycopg 3 默认 autocommit**。换库必查文档 | |
| 10 | `fetchone()` 查不到时返回什么 | `None`，不抛异常。先 `row = cur.fetchone()` 再 `if row is None:`，直接 `row[0]` 就是 `TypeError` | |
| 11 | 空表上 `AVG(score)` 返回什么 | SQL `NULL` → Python `None`，不是 0。函数签名要写 `-> float \| None` | |
| 12 | 默认行是什么形状，怎么变字典 | 默认**元组**。设 `conn.row_factory`（pymysql 用 `DictCursor`，psycopg 用 `dict_row`）；列名来自 `cursor.description[i][0]` | |
| 13 | `sqlite3.Row` 就是 dict 吗 | 不是。它是只读序列，能按名字下标，但 `!= dict`，也别指望 `dict.keys()` 那套 | |
| 14 | 批量插入怎么写 | `cursor.executemany(sql, list_of_tuples)`，一次发过去；for 循环里 `execute` 是 N 次往返 | |
| 15 | 影响行数、自增主键怎么看 | `cursor.rowcount`（UPDATE/DELETE 先看它判断成功）、`cursor.lastrowid`；连接累计改动看 `conn.total_changes` | |
| 16 | 为什么 `with conn.cursor() as cur` 在 sqlite3 会报错 | Python 3.14 里 `sqlite3.Cursor` **不支持上下文协议**（pymysql 的游标支持）。写 `cursor = conn.cursor()` | |
| 17 | upsert 有几种写法 | SQLite：`INSERT OR IGNORE`（只忽略）/ `ON CONFLICT(name) DO UPDATE SET score = excluded.score`（有则改）。别"先查再决定" | |
| 18 | "先 SELECT 判断余额再 UPDATE" 错在哪 | 两步之间有并发窗口（TOCTOU）。一条 `UPDATE … WHERE id = ? AND score >= ?` + 判 `rowcount == 0`，才原子 | |

## 一句话自检（背不出就回讲义 ⑤）

- 三个必踩的坑：忘了 `commit()`、把 `fetchone()` 的 `None` 当行用、f-string 拼 SQL（或妄想给列名用占位符）。
