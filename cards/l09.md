# L09 闪卡 · 模块、虚拟环境与依赖

> 用法：盖住右列，看左列自问自答，答完再对。做错的那行，在"错"列打 ×。
> 复习节奏：完成当天不算，D+1、D+2、D+4、D+7 各过一遍（`py progress.py review` 会告诉你今天该翻哪张）。

| # | 问 | 答 | 错 |
|---|---|---|---|
| 1 | Python 的"模块"对应 Java 的什么 | 一个 `.py` 文件就是一个模块（≈一个源文件级的命名空间），没有"一个 class 一个文件"的强制 | |
| 2 | `import m` 执行了什么 | **执行 m.py 的顶层代码**，结果缓存进 `sys.modules`；第二次 import 不再执行 | |
| 3 | `if __name__ == "__main__":` 干嘛用 | 脚本直跑时 `__name__` 是 `"__main__"`，被 import 时是模块名 —— 一段代码"可执行也可导入"的开关 | |
| 4 | 包(package)的最低要求 | 目录 + `__init__.py`（可为空，标记包并放包级代码）；3.3+ 有无 `__init__.py` 的命名空间包属进阶特例 | |
| 5 | 模块搜索顺序 | 内存缓存 sys.modules → `sys.path` 逐目录（脚本目录/当前目录 → PYTHONPATH → 标准库 → site-packages）→ 找不到 ModuleNotFoundError | |
| 6 | `import os.path` 之后名字绑在谁上 | 绑定名是 `os`，用 `os.path.join` 访问；`from os.path import join` 才直接把 join 带进当前命名空间 | |
| 7 | 循环导入怎么解 | 拆公共依赖到第三个模块 / 延迟到函数内部 import / 改用 `import m` 不用 `from m import x`；`from m import *` 是灾难放大器 | |
| 8 | `__pycache__` 和 `.pyc` | 编译好的字节码缓存，按源码 mtime 自动失效；删了无害，别提交进 git | |
| 9 | 三方库装在哪 | venv 的 `site-packages`（每个环境一套）；不带 venv 时 `pip install --user` 或直接污染全局 | |
| 10 | venv 三件套（Windows） | 建：`py -m venv .venv`；激活：`.venv\Scripts\Activate.ps1`（PowerShell）或 `activate.bat`；退出：`deactivate` | |
| 11 | 为什么敲 `py -m pip` 而不是 `pip` | 保证 pip 和你刚敲的 `py` 是同一个解释器，多版本共存时不装错地方 | |
| 12 | 依赖锁定 ≈ pom.xml 的什么 | `pip freeze > requirements.txt` 锁全部传递依赖；直接依赖手写进 `pyproject.toml [project].dependencies` | |
| 13 | 常用 pip 命令 | `install -r requirements.txt` / `list` / `show 包名` / `uninstall` / `install -U 包名` / `freeze` | |
| 14 | pyproject.toml 是什么 | 现代项目唯一入口：`[project]` 声明元数据+依赖，构建/工具配置也归它（≈ pom.xml 的地位） | |
| 15 | src 布局 vs flat 布局 | `src/包名/...` 强制从安装位置导入、测试更真；flat（包名直接放根）写 demo 快。Java 的 src/main/java 心智≈src 布局 | |
| 16 | 标准库判定怎么编程实现 | `sys.stdlib_module_names`（frozenset，3.10+）；区分 std/三方/本地是 import  lint 工具的基本功 | |
| 17 | Windows 上脚本入口为什么有时是 `py` 不是 `python` | `py` 是启动器，能选版本（`py -3.14`）；本教程统一用 `py` | |

## 一句话自检（背不出就回讲义 ②）

- 三个 Java 老手必踩的坑是：在项目根外面跑脚本导致 sys.path 不对、不带 venv 全局 pip 装包、
  requirements.txt 手写不 freeze 导致线上环境漂移。
