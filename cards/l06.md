# L06 闪卡 · 异常与上下文管理器

> 用法：盖住右列，看左列自问自答，答完再对。做错的那行，在"错"列打 ×。
> 复习节奏：完成当天不算，D+1、D+2、D+4、D+7 各过一遍（`py progress.py review` 会告诉你今天该翻哪张）。

| # | 问 | 答 | 错 |
|---|---|---|---|
| 1 | `try/except/else` 的 `else` 何时执行 | try 块**没抛异常**时执行；else 里的异常不会被本结构的 except 捕获 | |
| 2 | `finally` 何时执行 | 正常、异常、甚至 try 里 `return` 后都要执行。适合释放资源 | |
| 3 | `finally` 里写 `return` 的后果 | 会吞掉 try 中的异常和返回值。Java 里同样坏味道，Python 不报警告 | |
| 4 | `raise ParseError("x") from err` 的作用 | 设置 `__cause__`，traceback 显示"During handling... came from"。Java 对应 `initCause` | |
| 5 | 怎么隐藏异常链 | `raise NewError() from None`，`__cause__` 为空 | |
| 6 | `except Exception` 会吞 `KeyboardInterrupt` 吗 | 不会。它继承 `BaseException` 不继承 `Exception`。永远别写裸 `except:` | |
| 7 | 多个 except 的匹配规则 | 按书写顺序匹配，命中即停。**具体类型放前面**，基类放后面 | |
| 8 | 自定义异常该继承谁 | 继承 `Exception`（或其子类如 `ValueError`），不要继承 `BaseException` | |
| 9 | Python 有受检异常（checked exception）吗 | 没有。`raise` 随便抛，签名里没有 throws | |
| 10 | 能放进 `with` 的对象要满足什么 | 上下文管理器协议：`__enter__` / `__exit__(exc_type, exc_val, exc_tb)` | |
| 11 | `__exit__` 返回 True 意味着什么 | 异常被"消化"，不再向外传播。返回 False/None 则继续抛 | |
| 12 | Java 的 try-with-resources 对应物 | `with` 语句；`AutoCloseable.close()` ≈ `__exit__` | |
| 13 | 没有 with 协议但有 `close()` 的对象怎么办 | `contextlib.closing(obj)` 包一下 | |
| 14 | 只想吞某一类异常 | `with contextlib.suppress(KeyError): ...`，别写 try + pass | |
| 15 | `@contextmanager` 怎么写 | 生成器：yield 前=进入，yield 后放 `try/finally`=退出；不吞异常 | |
| 16 | EAFP 和 LBYL 的区别 | 先做、失败再 except（EAFP，Python 惯用）vs 先检查再做（LBYL，Java 惯用）| |
| 17 | 异常做流程控制的边界 | StopIteration / KeyError 等协议信号照常使用，但**业务分支不要用异常传值**，用返回值 | |
| 18 | try 块该多大 | 只包住"会失败的那一行"。大块 try 会连坐无关代码、掩盖真 bug | |

## 一句话自检（背不出就回讲义 ②）

- 三个 Java 老手必踩的坑是：裸 `except:` 吞一切、`finally` 里 return 吞异常、不用 `from` 丢了异常链。
