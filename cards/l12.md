# L12 闪卡 · 并发：GIL、线程、进程、协程

> 用法：盖住右列，看左列自问自答，答完再对。做错的那行，在"错"列打 ×。
> 复习节奏：完成当天不算，D+1、D+2、D+4、D+7 各过一遍（`py progress.py review` 会告诉你今天该翻哪张）。

| # | 问 | 答 | 错 |
|---|---|---|---|
| 1 | GIL 锁的是什么 | **解释器内部状态**（引用计数、内存分配）。同一进程内同时只有一个线程执行 Python 字节码 | |
| 2 | 有了 GIL 还需要 `Lock` 吗 | 需要。`x += 1` 是读-改-写三步，切换在步与步之间发生，照样丢失更新 | |
| 3 | 多线程对 I/O 密集有用吗 | 有用。线程阻塞在 I/O 时会**释放 GIL**，别的线程能继续跑 | |
| 4 | CPU 密集任务在 CPython 里怎么加速 | 上进程：`ProcessPoolExecutor` / `multiprocessing`，每个进程一份 GIL | |
| 5 | `Lock` 和 `RLock` 选哪个 | 默认 `Lock`；同一线程需要重复进同一把锁时才用 `RLock`（可重入） | |
| 6 | Java 的 `CountDownLatch(1)` 在 Python 是什么 | `threading.Event`：`set()` / `clear()` / `wait(timeout)` 返回 bool | |
| 7 | `CyclicBarrier` 的对应物 | `threading.Barrier(parties)`，`parties` 必须等于真正参与的线程数 | |
| 8 | 线程池里 `map` 与 `submit+as_completed` 的区别 | `map` 保输入顺序；`as_completed` 按完成先后，谁快谁在前 | |
| 9 | 子任务抛异常，`Future` 怎么处理 | 异常被存起来，调用 `future.result()` 时**在当前线程重新抛出** | |
| 10 | 多线程共享数据靠什么，进程呢 | 线程：直接共享对象 + `queue.Queue`；进程：内存是**复制**的，只能 `multiprocessing.Queue`/`Pipe`/`Manager` | |
| 11 | `queue.Queue` 空队列时 `get()` / `get_nowait()` | `get()` 阻塞（可给 timeout），`get_nowait()` 抛 `queue.Empty` | |
| 12 | Windows 上为什么必须写 `if __name__ == "__main__":` | spawn 启动方式会重新 import 主模块；没保护 → 子进程又生子进程，无限递归 | |
| 13 | `freeze_support()` 什么时候必须写 | 用 PyInstaller 等把程序打包成 exe 再跑多进程时，放在进程启动之前 | |
| 14 | 传给进程池的函数有什么限制 | 必须是模块顶层可 pickle 的函数（不能是闭包、lambda、局部函数），参数返回值同样要可 pickle | |
| 15 | `async def f()` 后面直接写 `f()` 会怎样 | 不执行函数体，只返回一个协程对象。要 `await`，并由 `asyncio.run()` 驱动 | |
| 16 | `gather` 和 `TaskGroup` 的区别 | `gather` 返回按传入顺序的结果列表；`TaskGroup`（3.11+）是结构化并发，任一失败自动取消其余 | |
| 17 | 协程里能不能用 `time.sleep` / `requests` | 不能，会卡死整个事件循环。用 `asyncio.sleep` / `aiohttp`，或 `await asyncio.to_thread(...)` 包一层 | |
| 18 | 什么情况下多线程也能吃满多核 | 计算发生在会释放 GIL 的 C 扩展里（`numpy`、`pandas` 部分算子、编解码） | |

## 一句话自检（背不出就回讲义 ②）

- 三个必踩的坑：把 GIL 当线程安全 / 当性能保障、协程里调阻塞函数、Windows 裸起进程池没加 `__main__` 保护。
