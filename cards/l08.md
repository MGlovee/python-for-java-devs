# L08 闪卡 · 装饰器与 Pythonic

> 用法：盖住右列，看左列自问自答，答完再对。做错的那行，在"错"列打 ×。
> 复习节奏：完成当天不算，D+1、D+2、D+4、D+7 各过一遍（`py progress.py review` 会告诉你今天该翻哪张）。

| # | 问 | 答 | 错 |
|---|---|---|---|
| 1 | `@dec` 放在 `def f` 上是哪句的语法糖 | `f = dec(f)`，**def 执行时**就完成替换，不是调用时才生效 | |
| 2 | 装饰器三要素 | 输入函数、闭包持有原函数、返回新函数（wrapper 参数惯例 `*args, **kwargs` 照单全收） | |
| 3 | 不写 `@wraps(func)` 的后果 | `f.__name__` 变成 "wrapper"、docstring 丢失、没有 `__wrapped__` 逃生口；堆栈/日志/序列化全被带偏 | |
| 4 | 怎么拿回未装饰的原函数 | `f.__wrapped__()`（前提：装饰器里写了 @wraps） | |
| 5 | `@repeat(3)` 和 `@repeat` 的区别 | 带参装饰器是三层：`repeat(3)` 先返回真正的装饰器 decorate，语法糖是 `@repeat(3)`，**括号必写** | |
| 6 | `@a @b def f` 的应用顺序 | **自下而上**：`f = a(b(f))`；调用时 b 的 wrapper 在内层先执行 | |
| 7 | 类装饰器是什么 | 参数是类、返回类（或替换物），`@dataclass`/`@add_repr` 都是它 —— 运行时版 Lombok | |
| 8 | Python 的 `@Override` 存在吗 | 没有等价物。`super().xxx` 写错名字运行时才炸；要靠 linter/mypy | |
| 9 | 类型注解什么时候生效 | **从不**在运行时强制，`def f(x: int): ...` 传 str 照样进函数体。注解是给人和 mypy/IDE 看的元数据（`f.__annotations__`） | |
| 10 | `list[str]` / `dict[str, int]` 对应 Java 的 | `List<String>` / `Map<String,Integer>`；小写下标、方括号内逗号分隔，3.9+ 直接可用 | |
| 11 | `str \| None` 怎么读 | "str 或 None"，≈ Java Optional<String> 的位置但只是类型声明；旧代码写作 `Optional[str]` | |
| 12 | TypeVar 的 T 何时"绑定" | **一次调用内**所有 T 位置类型一致：`first(items: list[T]) -> T`。比 Java 通配符简单直白 | |
| 13 | Protocol vs Java interface | 结构化子类型：不声明 implements，方法齐全即匹配（鸭子类型的静态版）| |
| 14 | mypy 是什么（一句话） | 离线类型检查器：`py -m mypy 文件`，不执行代码，只按注解报错 | |
| 15 | `x = a > b and a or b` 的坑 | a 为假值（0/空）时表达式塌向 b —— Python 2.5+ 一律写 `a if a > b else b` | |
| 16 | `[[0]*3]*5` 的坑 | 5 个引用指向**同一个**内层列表，改一格全行变；写 `[[0]*3 for _ in range(5)]` | |
| 17 | `is` 和 `==` 何时用哪个 | `is` 只用于 None/False/False 语义判断；数值比较永远 `==`（CPython 小整数缓存 [-5,256] 会骗你） | |
| 18 | 复杂三元堆叠怎么办 | 用辅助函数拆开（番外篇《用函数还是用复杂的表达式》）：可读性 > 行数 | |

## 一句话自检（背不出就回讲义 ②）

- 三个 Java 老手必踩的坑是：忘写 @wraps、装饰器栈顺序脑补反、把类型注解当成 Java 静态类型来信任。
