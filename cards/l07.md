# L07 闪卡 · 迭代器与生成器

> 用法：盖住右列，看左列自问自答，答完再对。做错的那行，在"错"列打 ×。
> 复习节奏：完成当天不算，D+1、D+2、D+4、D+7 各过一遍（`py progress.py review` 会告诉你今天该翻哪张）。

| # | 问 | 答 | 错 |
|---|---|---|---|
| 1 | 迭代器协议是哪两个魔术方法 | `__iter__`（返回迭代器）和 `__next__`（推进一格，耗尽抛 `StopIteration`）。没有 interface 关键字，魔术方法即协议 | |
| 2 | 可迭代对象(Iterable) vs 迭代器(Iterator) | 可迭代 = 能 `iter()` 出新游标（list/dict/str）；迭代器 = 一次性游标本身。`for` 脱糖为 `it=iter(x)` + 反复 `next` | |
| 3 | `iter([1,2]) is iter([1,2])` | False。列表每次给**新**游标；生成器是自身的迭代器，`iter(g) is g` 为 True | |
| 4 | `list(gen)` 之后再次 `list(gen)` | 第二次是 `[]` —— 生成器/迭代器只向前，不可重放 | |
| 5 | 调用生成器函数时函数体执行了吗 | 没有。返回生成器对象，**第一次 next 才跑到第一个 yield** | |
| 6 | `yield` 和 `return` 的本质区别 | yield 冻结现场、可恢复；return 直接结束。一个函数里出现 yield 它就是生成器函数 | |
| 7 | `yield from sub` 的作用 | 委托：把子迭代器的产出原样转给外层，少写一层 for-yield | |
| 8 | `gen.send(v)` 的 v 落在哪 | 成为生成器里 `yield` 表达式的值。用 send 前必须先用 next()（或 send(None)）prime 到第一个 yield | |
| 9 | 生成器表达式 vs 列表推导式 | `(x*x for x in s)` 惰性、占常量内存、一次性；`[x*x for x in s]` 立即全量。传参给 sum/max 时省掉 list 那层括号 | |
| 10 | 无限序列怎么消费 | `itertools.islice(无限, n)`。直接 `list()` 会吃到内存耗尽 | |
| 11 | cycle / chain / product / combinations / permutations | 无限循环 / 拼接可迭代 / 笛卡尔积 / 组合(无序不重复) / 排列(有序) | |
| 12 | groupby 的前提 | 只把**相邻**相同元素分组 —— 先 `sorted` 再用 | |
| 13 | `reduce(f, seq, init)` 干什么 | 左折叠：`init → f(init, x0) → f(…, x1)…`；初值保证空序列也有结果。求积/拼接常用 | |
| 14 | lru_cache 对递归的意义 | 指数级递归 → 线性（fib(100) 毫秒级）。参数必须可哈希；会拖住实例引用（方法上慎用） | |
| 15 | singledispatch 是什么 | 按**第一个参数的运行时类型**分派到不同实现，≈ Java 没有的"按参数类型重载"（Python 平时没有重载） | |
| 16 | Counter.most_common 并列时顺序可靠吗 | 不可靠（按插入序，非字典序）。要确定性输出就先 sorted 定全序 | |
| 17 | StopIteration 为什么"不该出现在"业务代码 | 它是 for/next 的协议信号；手动 next 时捕获可以，其余交给语法处理 | |
| 18 | 协程和 L12 的 async 什么关系 | `send` 版协程（yield 协作）是老式写法；`async/await` 是它的正式化，思想一致：阻塞时让出 CPU | |

## 一句话自检（背不出就回讲义 ②）

- 三个 Java 老手必踩的坑是：拿生成器当列表二次遍历、`list()` 无限序列、迭代器"可迭代≠可重复迭代"分不清。
