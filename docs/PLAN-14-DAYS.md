# 14 天冲刺方案 · 目标：爬虫 / 自动化 / 数据处理

> 这是与 [README](../README.md) 互补的一份**排期表**：材料完全相同，改变的是**顺序、取舍和复习间隔**。
>
> 每天投入 **3 小时 45 分**，14 天合计 **52.5 小时**，与"4 周 × 每天 2 小时 / 共 50 小时"的宽松版总量相当。
> 所以这不是"把 50 小时硬塞进 14 天"，而是**同一批小时数前置到两周，并留出缓冲**。

## 一、先看清这笔账

36–50 小时由四块组成（依据见 [how-to-learn.md](how-to-learn.md)）。压到两周靠下面四件事，
**不靠**"每天少睡一小时硬塞"：

| 手段 | 对总小时数的影响 | 说明 |
|---|---|---|
| ① 3 课降为速览，1 课只留最小一节 | **−5 小时** | 见第二节，砍的是对"爬虫 / 自动化"投入产出比最低的部分 |
| ② L15 从选做转必修 | **+2 小时** | 目标就是数据处理，原方案标成"选做"属于跟目标错配，不是省时间 |
| ③ 复习间隔 D+1/3/7/21 → D+1/2/4/7 | 0（但复习不排队） | 见第三节，不改这个，第 8 天起旧卡会挤占新课时间 |
| ④ 28 天摊薄 → 14 天集中 | 0 | 同样的事做更密的排布，密度本身就是改动 |

净 −3 小时，加上原方案里没被单独列出来的空隙，一起变成下表最右列的**约 6 小时缓冲**。
缓冲不是奢侈品，是解药：压缩方案唯一真实的失败模式是"第 5 天落后一天就崩盘"。
落后了就吃掉缓冲，别熬夜补 —— 熬夜补的那晚，第二天的提取练习成绩会掉。

**L05 / L08 / L09 / L14 降级理由**：

- **L05 面向对象**：爬虫项目里 class 的作用是*读懂别人的库*，不是设计类层次。`self` / `__init__` / `dataclass` 够用；

- **L08 装饰器**：目标是**能读懂** `@retry`、`@log_time` 并写一个最简单的；三层嵌套闭包推导不产生业务价值。
  类型注解一节**别跳** —— 读现代 Python 库全是它。
- **L09 模块与虚拟环境**：L01–L14 **零第三方依赖**，这两周不会发包也不会建虚拟环境。
  只保留"知道 `venv` 和 `pip install` 怎么按"的 15 分钟。
- **L14 测试与工程化**：`profile`、覆盖率、CI 全砍，只留一节 —— 给 P1/P2 的 `app.py` 各写 3 个测试。
  这是"自动化脚本能被别人接手"和"一次性脚本"的分界线，值得留。

## 三、为什么复习间隔要改成 D+1/2/4/7

Dunlosky 2013 那篇综述把 10 种学习方法排了序：**只有提取练习和间隔分布是高效用**，重读划重点都低效用。
但"间隔该多长"不是固定的 —— **Cepeda 等 2006 的元分析（317 个实验、839 组测量）给出的结论是：
最优间隔随需要保持的时间长度一起增长；保持期只有几天到几周时，集中练习（massed practice）就已经够用。**

宽松版用的 `D+1 / D+3 / D+7 / D+21` 是为"四周学完、长期不消"配的。
放进 14 天窗口会出现两个结构性问题：

1. `D+21` 那一轮**永远落在截止日之后** —— 占着一个复习槽却一次都不会触发，进度分母虚高；
2. 每天 2 门课的强度下，`D+3` 会和下一轮新课撞车，第 8 天开始旧卡排队挤掉新课。

改成 **`D+1 / D+2 / D+4 / D+7`**：四轮全部落在窗口内，最后一轮在学完 7 天后，正好在项目阶段（D7–D13）
被真实用到 —— **项目本身就是最长的那次间隔复习**。长期保持则由 D14 之后的月度全量回归接住，
那一轮顶替原来 `D+21` 的位置。

改动只有一处常量，`progress.py` 的排期算法会自动跟着走（已验证）：

```python
# progress.py
INTERVALS = [1, 2, 4, 7]
```

## 四、每天怎么用

全部命令都在**仓库根目录**执行，`check.py` 就在这一层。

Git Bash 每次开窗口先执行一次（否则讲义示例打中文会乱码）：

```bash
export PYTHONUTF8=1
```

```bash
python progress.py                       # 1. 今天该做什么、该翻哪几张卡
python check.py L03 -v                   # 2. 做练习，红了逐条看中文消息，只盯第一条
python progress.py read L03              # 3. 翻完闪卡打卡
python check.py L03 --solution           # 4. 怀疑题目有问题时，验参考答案是否全绿
python projects/P1-日志分析命令行/verify.py app.py   # 5. 项目验收
```

卡住 15 分钟以上才准看 `solution.py`；看完必须**合上文件凭记忆重写** —— 照抄一遍通过率 100%、记住 0。

两个注意点：`check.py` **一次只收一课**（`check.py L01 L02` 会报参数错误，要分两次跑；
不带参数则是全套 265 题）；项目验收脚本可以从根目录用相对路径直接跑，不必先进项目目录。

## 六、14 天后你手上会有什么

三个能跑、能验收、能放进简历的离线工具：

| 项目 | 对应方向 | 产出 |
|---|---|---|
| [P1 日志分析命令行](../projects/P1-日志分析命令行/README.md) | 自动化 | Nginx/access.log → PV/UV、状态码分布、Top-N URL、慢请求，带 argparse 和自写测试 |
| [P2 数据采集与入库](../projects/P2-数据采集与入库/README.md) | 爬虫 | HTML/JSON 样本 → 解析 → 清洗去重（URL 规范化）→ SQLite → 查询报告 |
| [P3 数据报表](../projects/P3-数据报表/README.md) | 数据处理 | pandas 读 CSV → 缺失/重复/异常值体检 → 分组聚合 → 汇总报表 |

**验收标准是"跑得出来且判分全绿"，不是"读完了"** —— 这两件事在研究里是不同的能力，
后者给你的"我会了"的感觉通常是假的。

D14 之后的保养节奏：每月跑一次 `python check.py`（判分本身只要几秒），
哪些课回落红了就重做那几课 —— 通常 30–60 分钟。这一轮顶替原来 `D+21` 的位置，
防的就是"学完三个月回到零基础"。

## 七、和宽松版（4 周）的关系

两套排期共用同一批讲义、练习、闪卡和项目，只差三样东西：

| 项 | 4 周宽松版 | 14 天冲刺版 |
|---|---|---|
| 每天投入 | 2 小时 | 3 小时 45 分 |
| 讲课顺序 | 一天一课，L15 选做 | 部分课程合并、L05/L08/L09/L14 降级为速览，L15 必修 |
| 复习间隔 | `D+1 / D+3 / D+7 / D+21` | `D+1 / D+2 / D+4 / D+7` |

想切回宽松版：把 `progress.py` 里的 `INTERVALS` 改回 `[1, 3, 7, 21]` 即可，
讲义、练习、闪卡、项目都不受影响。

时间宽裕时也可以只按上表的"主线"走，把缓冲分钟当机动时间 —— 落后一天就吃掉缓冲，不要熬夜补。
