# L04 · 函数与一等对象

> 读 40 分钟 · 练 50 分钟

函数你写过一万个。这一课讲的是**Python 的函数和你写过的函数不是同一种东西**：
它是值，能进字典、能当参数、能被返回；它的参数家族比 Java 灵活十倍；它的名字查找规则和
lambda 的捕获语义跟你熟的「effectively final」完全不一样。

## ② 差异地图

### 参数家族：一个签名里的六种参数

```python
def pos_only(a, b, /,             # 只能按位置传（3.8+）
             normal,              # 普通参数：位置或名字都行
             *, c=1, d=2,         # 星号之后只能按名字传（命名关键字）
             **kwargs):           # 收走所有多余关键字
    ...
```

| 写法 | 收到什么 | 关键点 |
|---|---|---|
| `def f(a, b)` | 按位置绑定 | 调用时数量必须对得上，否则 `TypeError` |
| `def f(a, b=1)` | `b` 可省 | **带默认值的必须排在无默认值之后** |
| `def f(*args)` | 多余位置参数 → **元组** | 对应 Java 的 varargs，但随时能和别人混用 |
| `def f(**kwargs)` | 多余关键字参数 → **字典** | Java 没有对应物，等价于传了一个 `Map<String,Object>` |
| `def f(*, a, b)` | `a`、`b` 只能用 `f(a=1, b=2)` | 强制调用方写名字，可读性极佳 |
| `def f(a, /)` | `a` 只能用位置传 | 内部改名不怕破坏调用方 |

调用侧的解包（Java 完全没有的东西）：`f(*[1, 2], **{'c': 3})`。

### 一等函数：Java 的对应物 vs Python

| 你想干什么 | Java | Python |
|---|---|---|
| 把函数存进集合 | `Map<String, IntBinaryOperator>` | `OPS = {'add': lambda x, y: x + y}` |
| 传函数给方法 | 接口 / lambda 表达式 / 方法引用 `String::length` | 直接传名字 `sorted(xs, key=len)`，**不加括号** |
| 函数返回函数 | 返回一个接口实例 | `return inner` |
| 部分应用 | 手写包装类 | `functools.partial(f, base=2)` |
| 复合 | `Function.andThen / compose` | 自己写 3 行，或 `reduce` 串起来 |
| 三元运算/映射过滤 | Stream `map/filter` | 内置 `map/filter` 返回**惰性迭代器**，或直接用推导式 |
| 归约 | `Stream.reduce` | `functools.reduce`（能用 `sum/any/all/max` 就别用它） |
| 重载 | `f(int)` / `f(String)` 共存 | **没有重载**。同名 `def` 后者直接覆盖前者；靠默认值 + `*args` 解决 |

`lambda` 的区别只有一条要记：它是**一个表达式**，不能写 `return`、不能塞语句、不能指定参数类型。
一行以上的逻辑就老实写 `def`。

### LEGB：名字到底去哪一层找

Python 的查找顺序是 **L**ocal → **E**nclosing（外层函数）→ **G**lobal（模块）→ **B**uiltin，
**且发生在运行时**。Java 的作用域是编译期静态的（局部 → 成员 → 静态 → 导入），迁移过来只有三件事会变：

| 情况 | Python 行为 |
|---|---|
| `for` / `if` 块里定义的变量 | **块不是作用域**，函数体外也能看见（L01 提过） |
| 内层函数读外层变量 | 直接读，没问题 |
| 内层函数**改**外层变量 | 必须 `nonlocal x`；否则 `UnboundLocalError`。改模块级变量要 `global x` |
| Java lambda 捕获局部变量 | 要求 effectively final |
| Python 闭包捕获局部变量 | 捕获的是**变量本身**，不是值的快照 —— 这就是第 ① 题第 3 问的答案来源 |

## ⑤ 三个 Java 老手必踩的坑

1. **默认参数只在 `def` 执行时求值一次**。`def f(items=[])` 的 `[]` 是**同一个列表对象**，
   被所有没传参的调用共享，于是攒出幽灵数据。写 `def f(items=None)` 再 `if items is None: items = []`。
   这是 Python 面试必考题，也是真实项目里最难查的 bug 之一。
2. **晚绑定**：闭包引用的是变量，不是值。
   `[lambda: i for i in range(3)]` 三个 lambda 共用同一个 `i`，循环结束 `i == 2`，全返回 2。
   要固化就在定义时用默认参数（`lambda i=i:`）或再造一层函数。
3. **没有重载，也没有编译期参数检查**。同名 `def` 写两遍后一个悄悄覆盖前一个；
   少传/多传参数只在**调用那一刻**才 `TypeError`；命名关键字参数按位置传不会被拦，只会被
   `*args` 吞掉（本课 test_08 抓的就是它）。Java 编译器替你做的检查，Python 要靠
   类型注解 + `mypy` + 测试补回来。

## ⑥ 现在回看开头 3 题

1. `b = 2`（第二个位置参数顶掉了默认值）、`args = (3,)`、`kwargs = {'x': 4}`。
   默认值不是"只能追加"，它占的就是那个位置。
2. `[1]`、`[1, 1]`、`[1, 1, 1]` —— **同一个列表对象**，不是每次都新建。坑 ⑤-1。
3. `[2, 2, 2]`。三个 lambda 共享同一个 `i`，取值发生在调用时，那时循环早已结束。坑 ⑤-2。
