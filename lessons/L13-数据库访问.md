## ② 差异地图（Java → Python）

| 主题 | Java (JDBC) | Python (DB-API 2.0) | 一句话提醒 |
|---|---|---|---|
| 规范 | JDBC 接口 | PEP 249 `DB-API 2.0` | `pymysql`/`psycopg`/`sqlite3`/`oracledb` 同一套动作 |
| 拿连接 | `DataSource.getConnection()` | `sqlite3.connect(path)` / `pymysql.connect(host=…)` | 模块级 `connect`，没有 builder |
| 语句 | `PreparedStatement` | `cursor.execute(sql, params)` | **游标**才是执行单元，连接只是工厂 |
| 占位符 | `?` | `?`（sqlite3）/ `%s`（pymysql、psycopg 客户端占位） | 换库要换占位符风格，其余逻辑不动 |
| 取结果 | `ResultSet` 游标前移 | `fetchone / fetchmany(n) / fetchall` | 一次性读进内存，大结果要 `fetchmany` 或服务端游标 |
| 行形状 | RowMapper / Map | 默认**元组**；`row_factory` / `DictCursor` 变字典 | 别再写 `row[0]`、`row[1]` 靠下标猜 |
| 事务 | `conn.setAutoCommit(false)` | 默认就是"隐式开事务"，要显式 `commit()` | `with conn:` 是最省心的写法 |
| 影响行数 | `executeUpdate()` 返回值 | `cursor.rowcount` | DDL/DML 后先看它再判断成功 |
| 关闭 | try-with-resources | `conn.close()`；`Cursor` **不一定**支持 `with` | sqlite3 的 Cursor 没有 `__enter__`，pymysql 的有 |
| 异常 | `SQLException` | `sqlite3.Error` / `pymysql.MySQLError`，常见子类 `IntegrityError`、`OperationalError` | 捕获库的基类，别裸 `except Exception` |
| 连接池 | HikariCP | 标准库没有；`SQLAlchemy` 池 / `DBUtils.PooledDB` | 见下面的"连接池概念" |
| ORM | Hibernate / MyBatis | SQLAlchemy 2.0 / Django ORM | 本课只导览，练习不用 |

### DB-API 2.0 五步流水线

```python
conn = get_connection()                 # 1. 连接
try:
    cursor = conn.cursor()              # 2. 游标
    cursor.execute(sql, params)         # 3. 执行（值永远走占位符）
    rows = cursor.fetchall()            # 4a. SELECT → 取数据
    conn.commit()                       # 4b. INSERT/UPDATE/DELETE → 提交
except Exception:
    conn.rollback()
    raise
finally:
    conn.close()                        # 5. 释放
```

Python 3 里更推荐让 `with` 替你写第 4、5 步：

| 写法 | 语义 |
|---|---|
| `with conn:` | **事务**上下文：块内正常结束 → `commit()`；抛异常 → `rollback()`。不关闭连接 |
| `contextlib.closing(conn)` | 只管关连接，不管事务 |
| `pymysql` 的 `with conn.cursor() as cur` | 自动关游标（sqlite3 的游标**不支持**） |

### 防注入：唯一正确的写法

```python
# 错：字符串拼接 / f-string / % 格式化 —— 用户输入变成了 SQL 语法的一部分
cursor.execute(f"SELECT * FROM student WHERE name = '{name}'")

# 对：值是值、语法是语法，由驱动安全绑定
cursor.execute("SELECT * FROM student WHERE name = ?", (name,))          # sqlite3
cursor.execute("SELECT * FROM student WHERE name = %s", (name,))         # pymysql

# 表名/列名/order by **没法参数化** → 白名单校验（练习里的 build_in_clause）
if not column.isidentifier() or column not in ALLOWED_COLUMNS:
    raise ValueError(f"非法列名 {column}")
```

| 场景 | 处理 |
|---|---|
| `IN (…)` 值个数不定 | 按个数生成 `"?, ?, ?"`，见练习 `build_in_clause`；空集合用 `WHERE 1 = 0` |
| 批量插入 | `cursor.executemany(sql, list_of_tuples)`，不要 for 循环里 `execute` |
| 建表/多语句脚本 | `conn.executescript(sql_text)`（sqlite3） |
| 返回自增主键 | `cursor.lastrowid` |
| 布尔/NULL | Python `True/False` ↔ 1/0，`None` ↔ `NULL`；反过来 `AVG()` 空集给 `None` |

### `sqlite3`（本课主力）与真数据库的差别

| 项 | `sqlite3` | `pymysql`（MySQL） | `psycopg`（PostgreSQL） |
|---|---|---|---|
| 安装 | 标准库，`import` 就有 | `pip install pymysql`（MySQL 8 认证还要 `cryptography`） | `pip install "psycopg[binary]"` |
| 连接串 | `sqlite3.connect("school.db")`，`:memory:` 可建内存库 | `pymysql.connect(host=, port=3306, user=, password=, database=, charset="utf8mb4")` | `psycopg.connect("host=… dbname=… user=… password=…")` |
| 占位符 | `?` | `%s` | `%s`（服务端预编译可用 `Pyformat`/`ClientCursor` 区分） |
| 取字典行 | `conn.row_factory = sqlite3.Row` 或自写函数 | `cursorclass=pymysql.cursors.DictCursor` | `row_factory=dict_row` |
| 自动提交 | 默认 False（隐式事务） | 默认 False | **默认 True**（autocommit）—— 最容易被坑的一点 |
| 类型亲和 | 弱（`INTEGER` 列能塞字符串） | 严格 | 严格，且类型最丰富（`jsonb`、数组、`uuid`） |
| 适用 | 单机工具、测试、嵌入式、P2 项目起步 | 线上业务库 | 新项目、复杂查询、JSON 字段 |

### 连接池概念（Java 人的直觉要换一档）

| 事实 | 影响 |
|---|---|
| `connect()` 很贵（TCP + 认证 + 会话变量） | 每次请求新建连接 = 延迟雪崩 |
| 数据库端 `max_connections` 有限（MySQL 默认 151） | 线程越多 ≠ 越快，连接数要**有上限** |
| Python 标准库没有池 | 用 `SQLAlchemy` 的 `QueuePool`（默认 pool_size=5, max_overflow=10）或 `DBUtils` |
| 用完必须归还/关闭 | `with` + `try/finally`；长事务会占着池里的连接不放 |
| 池参数经验值 | `pool_size ≈ 核数×2 + 有效磁盘数`，先小后大；配 `pool_pre_ping` 防"拿到已断的连接" |

### SQLAlchemy 2.0 是什么（讲义级导览，练习不用）

一句话：**把 DB-API 包装成 `Session` + `Engine`(自带池) + ORM 模型**，接近 Java 的 JPA/Hibernate。

```python
from sqlalchemy import create_engine, select, text      # 需要 pip install sqlalchemy
engine = create_engine("mysql+pymysql://user:pw@127.0.0.1:3306/hrs?charset=utf8mb4")

with Session(engine) as session:                        # Session 才是工作单元（≈ EntityManager）
    rows = session.scalars(select(Student).where(Student.score >= 85)).all()
    session.commit()

with engine.connect() as conn:                          # Core 层：手写 SQL 也有池和参数绑定
    conn.execute(text("UPDATE student SET score = :s WHERE id = :i"), {"s": 90, "i": 1})
    conn.commit()
```

| 层次 | 用什么 | 什么时候 |
|---|---|---|
| 裸 DB-API | `sqlite3` / `pymysql` | 脚本、迁移、要极致控制 |
| Core（`text()` + 命名参数 `:name`） | SQLAlchemy Core | 复杂 SQL 不想丢可读性 |
| ORM（模型类 + `Session`） | SQLAlchemy 2.0 | 多人协作的业务系统 |

## ⑤ 三个 Java 老手必踩的坑

1. **"我什么都没做，数据怎么没进库？"** —— Python 的 DB-API 默认在隐式事务里，
   不 `commit()`（或不用 `with conn:`）就永久丢失。JDBC `autocommit=true` 的直觉在 sqlite3/pymysql 上反过来了；
   而 psycopg 3 默认又是 autocommit，两个库行为相反，换库必查文档。
2. **`fetchone()` 返回 `None`，不是抛异常。** Java 里习惯 `if (rs.next())`，Python 里要写
   `row = cursor.fetchone()` 然后 `if row is None:`；直接 `row[0]` 就是 `TypeError: 'NoneType' object is not subscriptable`。
   另外 `AVG()`/`MAX()` 在空表上给 SQL `NULL` → `None`，别当 0 用。
3. **f-string 拼 SQL，或对表名/列名用占位符。** 前者是注入，后者根本跑不通（占位符只能替换**值**）。
   列名走 `isidentifier()` + 白名单，`IN (...)` 按值个数生成占位符。
   顺带一条小的：`sqlite3.Cursor` 不支持 `with`，从 pymysql 抄来的 `with conn.cursor() as cur` 在这里直接 `TypeError`。
