## ② 差异地图（Java → Python）

### pytest ↔ JUnit 5

| 主题 | JUnit 5 | pytest | 一句话提醒 |
|---|---|---|---|
| 用例发现 | `@Test` 注解 | 文件 `test_*.py` + 函数 `test_*`，测试类要 `Test*` 且不能写 `__init__` | 靠**命名约定**，没有注解 |
| 断言 | `assertEquals(exp, act, "msg")`、`assertThrows(X.class, () -> ...)` | `assert exp == act, "msg"`；`with pytest.raises(X, match="0~1") as e:`（`e.value` 是异常对象） | 失败时打印左右实际值：pytest 导入测试模块时**重写了 AST**；逗号必须在**外层**，写成 `assert (exp == act, "msg")` 断言的是元组 → 恒真。浮点用 `pytest.approx(0.3)`（默认 `rel=1e-6`），比 dict/set 先 `sorted()`——顺序不是契约。块内没抛 = 失败（练习 7 手写这套语义） |
| 前置 / 后置 | `@BeforeEach` / `@AfterEach` | `@pytest.fixture`：`yield` 前 setup、后 teardown，按**参数名**注入；`scope="function/class/module/session"` | 跨文件共享要放 **`conftest.py`**（同目录及父目录自动生效，不用 import）——"fixture not found" 的头号原因 |
| 参数化 / 标记 / 选跑 | `@ParameterizedTest` + `@CsvSource`、`@Disabled`、`@Tag` + `-Dgroups`、`mvn test -Dtest=X` | `@pytest.mark.parametrize("a, b", [(1, 2), (3, 4)])`；`skip(reason=...)` / `skipif(cond)` / `xfail` / `-m "not slow"`；`pytest -q -x --tb=short`、`-k 关键字`、`path::test_name` | **本机的替身不支持 parametrize 和 fixture**，装了真 pytest 才有；`xfail` 在 Java 没有对应物；自定义 marker 要在 `pytest.ini` 注册；结尾那行 `5 passed, 2 failed, 1 error, 4 skipped` 是**给人看的自由文本**（练习 4 解析它） |
| 覆盖率 / 不装包 | JaCoCo | `pytest --cov=src --cov-report=term-missing`（要 `pytest-cov`）；标准库方案：`unittest.TestCase` + `setUp/tearDown` + `self.assertRaises`，跑法 `py -m unittest -v` | 覆盖率只答"有没有跑到"，不答"断言够不够"；`unittest` 形状同 JUnit，但没有 fixture 注入和参数化糖 |

```python
import pytest                                # 本机没装 pytest：这段是"装了之后"的骨架，抄进项目能用


@pytest.fixture                                # ≈ @BeforeEach，按参数名注入
def prices():                                  # 放 conftest.py 就能跨文件共享
    yield [10.0, 20.0]                         # yield 之后是 teardown


@pytest.mark.parametrize("rate, expect", [(1.0, 30.0), (0.8, 24.0)])   # ≈ @ParameterizedTest
def test_discount(prices, rate, expect):
    assert discount_price(prices, rate) == pytest.approx(expect)


def test_bad_rate(prices):                     # ≈ assertThrows
    with pytest.raises(ValueError, match="0~1"):
        discount_price(prices, 9)
```

### logging ↔ SLF4J + Logback

| 主题 | Java | Python `logging` | 一句话提醒 |
|---|---|---|---|
| 级别与数字 | TRACE/DEBUG/INFO/WARN/ERROR | `NOTSET 0 / DEBUG 10 / INFO 20 / WARNING 30 / ERROR 40 / CRITICAL 50` | **数字越大越严重**；放行条件 `record.levelno >= logger.level`，**相等也放行**。`getLevelName("WARNING")` → `30`；认不出来时**不抛异常而是回字符串**：`getLevelName("info")` → `'Level info'`、`getLevelName(25)` → `'Level 25'`（练习 1、5 的坑） |
| 取 logger / 继承 | `LoggerFactory.getLogger(X.class)` | `logging.getLogger(__name__)`，点分名字自动成树：`shop.price.vip` 是 `shop.price` 的子节点 | `getEffectiveLevel()` 沿父链找**第一个设过的**级别，`NOTSET`(0) 视为没设；子级显式设了就用自己那份，**比父级更低也听它的**（练习 3） |
| 占位符 / 堆栈 | `log.info("uid {}", uid)`、`log.error("msg", e)` | `logger.info("uid %s", uid)`、`logger.exception("msg")` = `error(..., exc_info=True)` | 别预先 f-string：被级别挡掉时白格式化一遍；`exception` 只在 `except` 块里有意义 |
| 配置入口 | `logback.xml` | 生产用 `logging.config.dictConfig({...})`（四个键 `formatters/handlers/loggers/root`）；脚本用 `basicConfig`（**只配 root，且第二次调用无效**） | 库代码**不配置日志**，只 `getLogger` |
| 输出 / 格式 / 两道门 | Appender + PatternLayout + `additivity=false` | Handler（`StreamHandler`/`FileHandler`/`TimedRotatingFileHandler`/`SMTPHandler`）+ `Formatter("%(asctime)s %(levelname)s %(name)s %(message)s")` + `logger.propagate = False` | 模板吃的是 **`LogRecord` 的属性**（练习 5 手工造 record 就为看穿这点）；**两道门**：`record.levelno >= logger.level` **且** `>= handler.level`，取较严者——"日志不见了"九成卡在这（① 第 3 题）；测试里抓日志：私有 logger + `propagate=False` + `StreamHandler(io.StringIO())`，等价于 pytest 的 `capsys` |

### 性能 ↔ JMH / async-profiler

| 想答什么 | Java | Python | 注意 |
|---|---|---|---|
| 这段**多快** | JMH / `System.nanoTime()`（单调时钟） | `timeit.Timer(stmt).timeit(number)`；`repeat(repeat=3, number=500)` 取**最小值**；命令行 `py -m timeit -n 1000 -r 5 "expr"` | timeit 自动关 GC；单次耗时 = 总耗时 / number（练习 9）。手写计时至少用 `time.perf_counter()`，别用会被 NTP 拉回的 `time.time()` |
| **哪个函数**慢 | async-profiler / JFR | `py -m cProfile -s cumulative 脚本.py`；代码里 `Profile().runcall(f)` + `pstats.Stats(pr, stream=buf).sort_stats("cumulative").print_stats(10)` | `tottime` = 函数自身耗时（找热点），`cumtime` = 含被调用者（找链路瓶颈）。内存看 `tracemalloc`、压测看 Locust（原文有清单），本课不练；**别把耗时快慢写进断言**，CI 机器一慢就红 |

### 静态检查 ↔ Checkstyle / SpotBugs / javac

| 工具 | ≈ Java | 管什么 | 命令（本机没装，以后装了再跑） |
|---|---|---|---|
| `ruff` | Checkstyle + SpotBugs | 风格 + 常见可疑写法，一条命令快一个量级，顺带 `isort`；`flake8` 是老方案，`pylint` 更细也更吵（≈ PMD） | `ruff check --fix .`、`ruff format` |
| `mypy` | 你已有的 javac 直觉 | 静态类型；**渐进标注、运行时零强制**（见 L08） | `mypy --strict src/`（`pyright` 更快） |
| PEP8 | 规范文档本身 | 4 空格不用 Tab、行宽 79、函数/类前后两空行、方法间一空行、`import` 分标准库/第三方/自定义三段按字母序；命名：函数变量 `snake_case`、类 `CapWords`、常量 `UPPER_SNAKE` | 练习 10 复刻其中一条：合法名 = `re.fullmatch(r"_*[a-z][a-z0-9_]*", name)`，违规报 `L{行号}: N802 函数名应使用 snake_case: {名字}` |

`argparse`（练习 6）↔ picocli：`parser.add_argument("-c", "--count", type=int, default=1)`（不写 `type=` 就是
字符串）、开关 `action="store_true"`、结果 `vars(parser.parse_args(argv))`；**参数非法时它把用法打到 stderr 再
`SystemExit`**，不是 `ValueError`——别 catch ValueError。

## ③ 完整样例：读 → 跑 → 改

下面这段 `py -X utf8` 直接跑：不联网、不落盘，日志和抓输出全走 `io.StringIO`。

```python
import io
import logging
import timeit


def discount_price(prices, rate):                  # 被测代码
    if not 0 <= rate <= 1:
        raise ValueError(f"折扣必须在 0~1，收到 {rate}")
    logging.getLogger(__name__).debug("算价 %d 条 rate=%s", len(prices), rate)
    return round(sum(p * rate for p in prices), 2)


sink = io.StringIO()                               # 练习 8 抓 print 也是这套 StringIO
app = logging.getLogger("shop.price")              # 练习 1-3：级别是阈值、名字自动成树
app.setLevel(logging.DEBUG)                        # 第一道门：logger
app.propagate = False                              # 不冒到 root，别人的配置影响不到这里
gate = logging.StreamHandler(sink)
gate.setLevel(logging.WARNING)                     # 第二道门：handler 自己也过滤
app.addHandler(gate)
child = logging.getLogger("shop.price.vip")        # 没设级别 → 继承 shop.price 的 DEBUG
inherited = logging.getLevelName(child.getEffectiveLevel())
child.setLevel(logging.INFO)                       # 显式设过 → 用自己那份，即使更低
for level in (logging.DEBUG, logging.INFO, logging.WARNING):
    app.log(level, "%s 级记录", logging.getLevelName(level))
print(f"logger=DEBUG 放行 3 条，handler=WARNING 只剩 {len(sink.getvalue().splitlines())} 行")
print(f"子 logger：继承的是 {inherited}，显式设 INFO 后 {logging.getLevelName(child.getEffectiveLevel())}")
try:
    discount_price([1.0], 9)
except ValueError as exc:                          # 练习 7 expect_raises 的手感
    print(f"异常消息：{exc}｜认不出的级别名：{logging.getLevelName('info')!r}")
unit = min(timeit.Timer("discount_price([10.0, 20.0], 0.8)", globals=globals()).repeat(3, 500)) / 500
print(f"练习 9 的味道：单次 {unit * 1e6:.1f} 微秒（取 repeat 最小值，别断言它）")
```

## ⑤ 三个 Java 老手必踩的坑

1. **库代码里调 `logging.basicConfig()`，或模块级 `logging.warning(...)`**。快捷函数**隐式配置 root
   logger**，`basicConfig` 又只有第一次调用有效；后果是宿主应用的配置被你改掉、测试之间日志串味。
   规则：库里只 `logger = logging.getLogger(__name__)`，**一个 handler 都不加**，配置权交给应用入口。
2. **`assert` 的括号包错地方 → 断言静默失效**。`assert (a == b, "消息")` 断言的是**元组**，非空元组恒真，测试永远绿。
   Java 的 assert 要 `-ea` 才生效，Python 默认真执行，但 `python -O` 会**整行删掉**——业务校验一律写 `if ...: raise ValueError(...)`。
3. **"我这台机器快 3 倍"和"用例互相污染"**。计时交给 `timeit`（自动关 GC、`repeat()` 取最小值），别用 `time.time()`
   单次采样，更别把快慢写进断言；浮点比 `pytest.approx`。用例之间别共享可变对象：`[[0] * 3] * 5` 是 5 个引用指向
   **同一个**列表（[番外篇那个坑](https://github.com/jackfrued/Python-100-Days/blob/master/%E7%95%AA%E5%A4%96%E7%AF%87/%E9%82%A3%E4%BA%9B%E5%B9%B4%E6%88%91%E4%BB%AC%E8%B8%A9%E8%BF%87%E7%9A%84%E9%82%A3%E4%BA%9B%E5%9D%91.md)）。

## ⑥ 现在回看开头 3 题

1. 它落到 **root logger** 上并隐式 `basicConfig()`，把库的日志和全局配置绑死。库代码只 `getLogger(__name__)`
   + `logger.warning(...)`、不加 handler；root 没 handler 时由 `lastResort` 兜底（WARNING 以上打到 stderr）。
2. 逗号在括号**里面**，断言对象是元组 → 恒真。改成 `assert total == 100, "金额不对"`。判分器里 test_13
   专测"该抛没抛"：`expect_raises(lambda: None, RuntimeError)` 必须给你个 `AssertionError`。
3. **不输出**：logger 放行（`INFO >= INFO`）但 handler 拦下（`INFO < WARNING`）——③ 里三条日志进 `WARNING` 门只剩 1 行。
   子 logger 没设级别（`NOTSET`）→ 沿父链借级别；显式设了就用自己那份，**即使更低**（`effective_level(DEBUG, ERROR)` → 10）。
   反向坑：`getLevelName("info")` 不抛异常而回 `'Level info'`，所以 `format_log_record("app", 25, "boom")` → `"Level 25|app|boom"`（test_08）。
