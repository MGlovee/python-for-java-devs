Java 里你写 `Iterator<T>`、`Stream<T>`、`implements Iterable<T>`，靠接口约束。
Python 里同样的机制存在，但没有接口关键字——**魔术方法就是协议**，而且 `yield` 把大半
样板代码消掉了。这一课讲清楚：协议本身、惰性、`send` 协程，以及 itertools/functools 这
两个"标准库 JDK"。

## ② 差异地图（只列你缺的那 20%）

| 主题 | Java | Python | 一句话提醒 |
|---|---|---|---|
| 迭代协议 | `interface Iterator<T>` + `hasNext()/next()` | 魔术方法 `__iter__` / `__next__` | 没有 hasNext；**耗尽时抛 `StopIteration`** 当结束信号 |
| 可迭代 | `Iterable<T>` 接口 | 实现了 `__iter__` 的一切 | `for x in obj` 脱糖 = `it = iter(obj)` + 循环 `next(it)` 捕 StopIteration |
| 协议声明 | `implements` 关键字 | 鸭子类型 | Python 中没有 protocol/interface 关键字，魔术方法名即协议（原文 31 课原话） |
| 惰性序列 | `Stream<T>`（还要 collect/close，心智负担大） | 生成器 / 生成器表达式 | 一次性游标，用完即弃，无 checked 异常 |
| 协程 | 无原生对应（虚拟线程 Loom 也不等价） | 生成器 + `send()`；`async/await` 是它的正式化 | L12 细讲 asyncio，这里先懂 `send` |
| 无限流 | `Stream.iterate()` | `itertools.count/cycle` + `islice` 截断 | 对无限生成器 `list()` = 内存爆炸 |
| 缓存递归 | 手写 HashMap / Guava Cache | `@lru_cache` 一行 | fib(100) 从算不完到毫秒 |
| 按类型重载 | 编译期方法重载 | **没有重载**；用 `@functools.singledispatch` | 后注册的类型分支更优先匹配 |

### 可迭代 vs 迭代器：一次说透

```python
nums = [1, 2, 3]
a, b = iter(nums), iter(nums)   # 列表是"可迭代对象"：每次 iter() 得到独立游标
next(a)                          # 1
next(a)                          # 2  —— b 不受影响

g = (x for x in nums)            # 生成器既是可迭代对象也是迭代器
iter(g) is g                     # True！它只有一个游标
```

所以：**列表能反复 `for`，生成器只能消费一次**。函数返回序列时，想省内存就返回生成器，
想让用户反复遍历/测长度就返回列表。

### `yield`：可恢复的函数

```python
def fib_gen(num):                # 带 yield 的函数体，调用时一行都不执行
    a, b = 0, 1
    for _ in range(num):
        a, b = b, a + b
        yield a                  # 产出 a 并冻结；下次 next() 从这里醒来
```

迭代器类 `Fib` 要写 `__init__/__iter__/__next__` 三个方法（原文 31 课的例子），
生成器版本 4 行。`yield from sub` 则把内层生成器的产出、耗尽信号、异常转发全部代劳。

### 生成器进化为协程（`send`）

`yield` 不只是"产出"，它还是个**表达式**，`gen.send(v)` 送进来的值就是它的结果：

```python
def calc_avg():                  # 流式计算平均值 —— 原文 31 课的例子
    total, counter, avg = 0, 0, None
    while True:
        value = yield avg        # 挂起等喂数据
        total, counter = total + value, counter + 1
        avg = total / counter

gen = calc_avg()
next(gen)                        # priming：先推进到第一个 yield，之后才能 send
gen.send(10)                     # 10.0
gen.send(20)                     # 15.0
```

这就是"协作式并发"的雏形——番外篇协程一文里 `async def` + `await` 干的是同一件事：
**子程序主动让出执行权，而不是线程那样被剥夺**。`await` 是高级货，但心智模型在这儿。

### `itertools` 常用件（背下这 10 个够干活）

| 函数 | 干什么 | 备注 |
|---|---|---|
| `count / repeat / cycle` | 无限数流 / 重复 / 无限循环 | 必须配 `islice` |
| `islice(it, n)` | 从任意可迭代取前 n 个（切片语义） | 不伤原迭代器分毫 |
| `chain(*its)` | 多个可迭代串成一条 | 替代 list 拼接 |
| `product(a, b)` / `permutations` / `combinations` | 笛卡尔积 / 排列 / 组合 | 原文点名"ABCD 全排列"三件套 |
| `groupby(it)` | 相邻相同元素成组 | **必须先排序** |
| `accumulate(it)` | 前缀和（可传运算符） | 减法版差分也行 |
| `compress(it, mask)` / `zip_longest` | 掩码筛选 / 按长的补齐的 zip | zip 截断到短的 |

### `functools` 三件

```python
from functools import reduce, lru_cache, singledispatch

reduce(mul, nums, 1)             # 左折叠 —— Stream.reduce 的近亲，初值放第三个参数

@lru_cache(maxsize=None)         # 带参数的装饰器（L08 讲原理），递归函数的救命药
def fib(n): return n if n < 2 else fib(n-1) + fib(n-2)

@singledispatch                  # 按第一个参数的运行时类型分派
def describe(x): return "?"
@describe.register
def _(x: int): return f"整数 {x}"
```

## ⑤ 三个 Java 老手必踩的坑

1. **把生成器当 List 用**。`users = gen_users()` 之后：`for` 两遍第二遍是空的、
   `len(users)` 直接 TypeError、传给 `sum()` 倒是没问题。要复用就 `list()` 落地，
   要明确只要一遍就保持惰性。
2. **`list()` 一个无限序列**。`itertools.cycle`、`count()`、`while True: yield` 都是合法的
   无限生成器，`list()` 下去直到内存耗尽。取前 n 个永远用 `islice`。
3. **并列统计依赖 `most_common` 的顺序**。`Counter.most_common` 对相同次数的词按插入序，
   跨版本跨数据不稳定；判分题里必须自己 `sorted(items, key=lambda kv: (-kv[1], kv[0]))`
   定全序。同理，别依赖 dict 的遍历顺序做断言。
