> 读 40 分钟 · 练 50 分钟

Java 的依赖心智是：Maven/Gradle + classpath + jar。Python 的对应物是：模块即文件 + `sys.path` +
pip + **venv**。最大的认知落差只有一个——**Python 没有"项目级依赖"的默认概念**，
不建虚拟环境，所有项目共用一个全局包目录，冲突了才发现没法收拾。这一课把命令和目录结构一次给全。

## ② 差异地图（只列你缺的那 20%）

| 主题 | Java | Python | 一句话提醒 |
|---|---|---|---|
| 命名空间单位 | 包 = 目录 + package 声明 | **模块 = 一个 .py 文件**，包 = 目录 + `__init__.py` | 文件名就是模块名，一个文件一个命名空间 |
| import 语义 | 编译期符号解析 | **运行时执行那个文件**，结果缓存进 `sys.modules` | import 的模块顶层代码有副作用（连 DB 都会当场连） |
| 搜索路径 | classpath / 模块系统 | `sys.path` 列表：脚本目录 → PYTHONPATH → 标准库 → site-packages | 找不到就 `ModuleNotFoundError`，先想"装了吗"再想"路径对吗" |
| 入口 | 固定 `public static void main` | `if __name__ == "__main__":` | 同一文件"可执行也可导入"的开关 |
| 可见性控制 | 包私有/public，`import *` 非法 | 没有语言级限制；`__all__` 只是给 `import *` 的约定 | 单下划线 `_x` = "内部用"的君子协定 |
| 循环依赖 | 编译器允许任意互引 | `from a import x` 在循环时可能拿到半初始化模块直接报错 | 解法见下方专段 |
| 字节码缓存 | 一个 .java 对一个 .class，手动编译 | `__pycache__/xxx.cpython-314.pyc` 自动生成、源码变了自动失效 | 别提交进 git，删了也无害 |
| 包管理器 | Maven/Gradle | **pip**（建议永远 `py -m pip`） | 现代项目元数据在 `pyproject.toml` |
| 环境隔离 | JDK 全局 + 依赖跟项目走 | 依赖跟**环境**走 → 每个项目一个 venv | 这是 Python 团队事故率最高的一条 |

### 模块与包：最小可行结构

```
src 布局（正式项目，≈ Maven 的 src/main/java）        flat 布局（小脚本）
myproj/                                                 myproj/
  pyproject.toml                                          src/ 或直接在根放包目录
  src/                                                  app.py
    myproj/                                               mypkg/
      __init__.py           ← 包标记，可为空                __init__.py
      core.py               ← 模块，import myproj.core      util.py
      util.py
  tests/                                                tests/
```

- `import myproj.core` 后用 `myproj.core.f()`；`from myproj.core import f` 直接把 `f` 带进来。
  两者最终都执行整个 `core.py`。
- `import os.path` 绑定的名字是 `os`（逐级加载，`os.path` 不是独立变量名）。
- `from m import *` 尽量别写，读代码的人（包括三个月后的你）无法追溯名字来源。

### 循环导入：成因与三种解法

Java 的类可以互相引用，因为解析发生在运行时之前；Python 的 `from a import x` 发生在
"a 只执行了一半"的时刻，拿不到 `x` 就炸 `ImportError: cannot import name`。

1. **拆**：把 a、b 共用的东西抽到第三个模块 c，a→c←b。最干净。
2. **改形式**：`from a import x` 改成 `import a` 后用 `a.x`，执行时机整体后移。
3. **延迟**：把 import 挪进函数体，调用时才导。急救可用，多了就是架构债。

### 环境三件套（Windows，照做即可）

| 想干什么 | 命令（PowerShell） |
|---|---|
| 给项目建环境（项目根目录） | `py -m venv .venv` |
| 激活（PowerShell） | `.venv\Scripts\Activate.ps1`（受限策略报错先 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`）|
| 激活（cmd） | `.venv\Scripts\activate.bat` |
| 看当前环境里的包 | `py -m pip list` / `py -m pip show requests` |
| 装一个包并记进依赖 | `py -m pip install requests` |
| 导出**全量**锁定文件 | `py -m pip freeze > requirements.txt` |
| 按文件装 | `py -m pip install -r requirements.txt` |
| 升级 / 卸载 | `py -m pip install -U 包名` / `py -m pip uninstall 包名` |
| 退出环境 | `deactivate` |
| 更新 pip 自己 | `py -m pip install -U --user pip`（原文 22 课 Windows 版命令） |

激活后提示符出现 `(.venv)`；此后 `python`/`pip` 都指向 `.venv` 内部。
**新终端要重新激活**。`.venv` 目录务必进 `.gitignore`。

### 依赖声明：requirements.txt 与 pyproject.toml

```toml
# pyproject.toml —— 项目"身份证"，直接依赖写这里（≈ pom.xml 的 <dependencies>）
[project]
name = "myproj"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = ["flask>=2.0", "requests>=2.31"]

[build-system]
requires = ["setuptools>=68"]
build-backend = "setuptools.build_meta"
```

分工：`pyproject.toml` 声明**直接依赖**（人写）；`requirements.txt`（由 `pip freeze` 生成）
锁定**全量传递依赖**（机器写，部署用）。原仓库 91 课把"库的依赖关系定义"列为必须进版本控制的
五类资产之一——对 Python 就是这两个文件 + 锁版本纪律。

标准库 / 三方 / 本地怎么程序化区分？`sys.stdlib_module_names`（3.10+ 的 frozenset）就是官方答案，
练习题全围绕它设计。

## ⑤ 三个 Java 老手必踩的坑

1. **`python xxx.py` 满世界跑，import 全靠运气**。`sys.path[0]` 是**脚本所在目录**不是你的
   当前目录：`py src/app.py` 能找到 `src/` 里的包，`py .\src\sub\tool.py` 就找不到 `src` 根的包。
   正确姿势：`py -m myproj.core` 从包的角度跑，或固定从项目根启动，别在 shell 里
   `cd` 来 `cd` 去还换脚本路径。
2. **不带 venv 就 `pip install`**。全局解释器被各项目版本互相覆盖，等于把依赖装进了
   `C:\Windows`——三个月后谁都说不清 `flask` 是谁、哪个版本。建项目第一条命令是 `py -m venv .venv`。
3. **requirements.txt 手写不 freeze**。只记直接依赖，部署机器上解析到的传递依赖版本和你
   开发时不同，"我机器上是好的"就诞生了。发布前 `py -m pip freeze > requirements.lock.txt`
   锁全量；开发期允许浮动，部署期必须锁定——和 Java 用 BOM/lockfile 是同一个道理。

## ⑥ 现在回看开头 3 题

1. **执行一次**。第一次 import 完整跑那个文件，之后缓存于 `sys.modules`，再 import 只是取缓存。
2. **`if __name__ == "__main__":`**。直跑时 `__name__` 为 `"__main__"`，被导入时为模块名。
3. 直接依赖写 **`pyproject.toml`** 的 `[project].dependencies`，全量锁定用
   **`requirements.txt`**（`py -m pip freeze` 生成）。
