## ② 差异地图（只列你缺的那 20%）

| 主题 | Java | Python | 一句话提醒 |
|---|---|---|---|
| 关键字 | `try/catch/finally` | `try/except/else/finally` | **`else` 是 Java 没有的**：try 没炸才执行 |
| 抛出 | `throw new X()` | `raise X()` | 抛的必须是实例；`raise X`（类）是编程错误 |
| 受检异常 | 有，签名带 `throws` | **没有** | 任何函数随时可能抛任何异常，读代码时别指望签名 |
| 异常顶层 | `Throwable` | `BaseException` | 下面分 `SystemExit` / `KeyboardInterrupt` / `GeneratorExit` / `Exception` |
| 日常捕获 | `catch (Exception e)` | `except Exception as e` | 语义一致：**都不该捕最顶层**（Java 里是 `Throwable`） |
| 异常链 | `new X(cause)` / `initCause` | `raise X from err` | 挂到 `__cause__`，traceback 自动多打一段 "came from" |
| 多类型捕获 | `catch (A \| B e)` | `except (A, B) as e` | 就是个元组 |
| 重抛 | `throw e` | `raise`（裸写） | 在 except 块里裸 `raise` = 原样重抛，保留现场 |
| finally 里的 return | 编译器警告 | **静默吞掉异常** | 语言不拦你，自己拦自己 |
| 资源管理 | `try (var f = open())` | `with open(...) as f:` | `with` 不限于资源，是通用的"协议对" |
| 判空再取 | `map.containsKey` 后 get（LBYL） | 直接取、`except KeyError`（EAFP） | Python 惯例：**先做了再说**，检查反而是异味 |

### `try/except/else/finally` 四段式的执行表

```python
try:
    value = int(data[key])        # 只把"会炸的一两行"放进来
except (KeyError, ValueError) as e:
    value = None                  # except 命中就不再往下走
else:
    log.append(value)             # 只有 try 没抛异常才执行；这里的异常不被上面的 except 捕获
finally:
    audit.append("done")          # 正常/异常/return，统统执行
```

四个块都不是必需，但 `except` 和 `finally` **至少有一个**。`else` 的价值：把"成功了再做的事"
从 try 里挪出去，避免误捕获 log.append 自己的异常。

### 异常层级：一张 Java 心智对照图

```
BaseException                 ≈ Throwable（但别直接捕它）
 ├── SystemExit                ≈ System.exit() —— 不该被业务代码吞
 ├── KeyboardInterrupt         ≈ Ctrl+C —— 不该被业务代码吞
 ├── GeneratorExit             （L07 生成器用）
 └── Exception                 ≈ Exception —— 日常捕获从这层开始
      ├── StopIteration        （迭代协议信号，for 循环内部靠它收尾）
      ├── ValueError / TypeError / KeyError / LookupError
      ├── OSError ── FileNotFoundError / PermissionError / TimeoutError
      └── RuntimeError ── NotImplementedError
```

自定义异常继承 `Exception`（或语义合适的子类，如 `ValueError`），命名按 PEP8 用
`XxxError` 大驼峰。业务异常层级就像 Java 的 `ServiceException → PaymentException`，
一个 `except OrderError` 捞起一族子类。

### 异常链：`raise ... from`

```python
try:
    port = int(raw)
except ValueError as err:
    raise ConfigError(f"端口配置非法: {raw!r}") from err   # __cause__ = ValueError
    # raise ConfigError(...) from None                     # 或干脆掐断链，隐藏内部细节
```

不写 `from` 时 Python 也会自动记 `__context__`（"处理期间又抛了"），但那不是你主动声明的
因果；日志里两种都会打出来，看清 "The above exception was the direct cause of..." 还是
"During handling of the above exception, another exception occurred"。

### `with` 协议 = AutoCloseable 的推广

只有实现了 `__enter__` / `__exit__` 的对象能进 `with`：

```python
class TaggedBlock:
    def __enter__(self):            # ≈ try-with-resources 的构造 + 进入
        print("<b>")
        return self                 # 返回值绑定给 as 变量
    def __exit__(self, exc_type, exc_val, exc_tb):   # ≈ close()，但多收 3 个异常参数
        print("</b>")
        return False                # True = 我已消化异常；False/None = 继续向外抛
```

`with a() as x, b() as y:` 支持多个；一行太长可以换行写。**锁、临时目录、数据库事务**
都是上下文管理器，`with lock:` 就是 `synchronized` 的迷你版。

懒人三件套（`contextlib`，标准库）：

| 想要的效果 | 写法 |
|---|---|
| 手写 `__enter__/__exit__` 太啰嗦 | `@contextmanager` 装饰生成器：yield 前=进入，`try/finally` 里 yield 后=退出 |
| 只想吞某类异常 | `with suppress(KeyError): d.pop(k)` |
| 对象只有 `close()` 没有协议 | `with closing(conn): ...` |

### EAFP 的边界

`try/except` 是 Python 的**默认风格**（字典取值、int 转换、文件打开），但原文总结里那句警告
要刻在脑门上：**不要用异常处理正常业务逻辑或控制程序流程**。协议信号（`StopIteration`、
`KeyError`）该捕就捕；"余额不足"这种业务分支该返回结果对象/抛给最外层统一处理，而不是在
调用链每一层都拿异常当 `if` 用。

## ⑤ 三个 Java 老手必踩的坑

1. **裸 `except:` 和 `except Exception: pass`**。前者连 `SystemExit`/`KeyboardInterrupt`
   都吞（Java 里你得写 `catch (Throwable)` 才这么狠，IDE 还会红字警告你）；后者静默丢弃 bug。
   只捕你明确能处理的类型；真要吃掉，用 `suppress(X)` 把"我是故意的"写在脸上。
2. **`finally` 里 `return`（或抛新异常）会吞掉 try 中的原异常**。Java 编译器至少给你个
   warning，Python 一声不吭。释放资源用 `finally`，别在里面改变控制流。
3. **重抛丢链**。`except ValueError: raise ConfigError(...)` 不写 `from err`，排障时只剩
   最后一层；`raise` 裸写可原样重抛，包新异常必须 `from`。另外别学 Java 那样
   "捕获再抛出同一个异常"绕一圈——原文总结明确不建议，除非你加了上下文。

## ⑥ 现在回看开头 3 题

1. **没抛异常时执行**。Java 没有对应物；它存在的意义是把成功路径移出 try，防止误捕。
2. 挂成了新异常的 **`__cause__`**，traceback 会先打原始 ValueError 再打 "The direct cause"。
   不想要链就 `from None`。
3. **捕不到**。`KeyboardInterrupt` 继承 `BaseException` 不继承 `Exception` —— 这正是你
   应该 `except Exception` 而不是裸 `except` 的原因。
